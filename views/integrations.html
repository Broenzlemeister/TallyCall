Trigger und Integrationen

Tallycall sendet bei Ereignissen Nachrichten an Medienserver, Lichtpulte und Co. (HTTP, OSC, TCP, UDP) und lässt sich von Companion, Stream Deck oder OSC steuern.

Ziele

Ein Ziel ist ein Gerät oder Dienst. Pixera: TCP/HTTP auf Port 1400 (JSON-RPC) · QLab/Resolume/grandMA: OSC · Companion: HTTP auf Port 8000.

Regeln gelten für alle Punkte

Bei jedem Ereignis die Nachricht an das Ziel senden. Platzhalter:

{title} {subtitle} {presenter} {id} {day} {show} {next} {remaining} {remainingSec} {clock} {cue} {gewerk} {gewerkShort} {message} {lowerTitle} {ready} {event}

Trigger für einzelne Punkte oder Cues legst du in der Planung direkt am Punkt an (⚡).

Sendeprotokoll

Steuerung von außen

Companion (Stream Deck), Browser-Favoriten oder jedes Gerät, das eine URL aufrufen kann, steuern die Show über einen API-Schlüssel.

Befehle per URL
Companion-Modul

Das Modul liegt im Repo im Ordner „integrations/companion“. In Companion: Einstellungen → Entwickler-Modulpfad auf den Ordner setzen, Verbindung „Tallycall“ anlegen, Adresse, Projekt-ID und Schlüssel eintragen. Es bringt Aktionen (Start, Weiter, Pause, Zeit, Bauchbinde, Nachricht, Bereit), Rückmeldungen (Status, Warnfarbe, Gewerk bereit) und Variablen (Titel, Restzeit, Nächster Punkt) mit.

OSC-Eingang

So triggerst du Pixera

  1. Ziel anlegen: Typ TCP, Host = IP des Pixera-Rechners, Port 1400. In Pixera unter Settings → API den Port aktivieren.
  2. Nachricht als JSON-RPC, zum Beispiel:
    {"jsonrpc":"2.0","id":1,"method":"Pixera.Timelines.Timeline.play","params":{"handle":12345}}\n
    Das „\n“ am Ende wird als Zeilenumbruch gesendet.
  3. Die Nachricht als Regel (bei „Start“), als Trigger an einem Punkt oder an einem Cue hinterlegen.

Läuft Tallycall online (tallycall.com) und Pixera im Veranstaltungsnetz, erreicht der Server das Gerät nicht. Dann triggert Companion vor Ort: Es hört auf Tallycall und sendet an Pixera. Ein lokaler Tallycall-Server sendet direkt.
